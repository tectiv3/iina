## Project Overview

IINA is a modern video player for macOS built on mpv. It's written primarily in Swift with Xcode as the build system. The project requires the latest public version of Xcode.

## Build Commands

### Initial Setup
```bash
# Download pre-compiled mpv/FFmpeg libraries (required for first build)
./other/download_libs.sh
```

### Build
```bash
# Build with Xcode
xcodebuild -project iina.xcodeproj -scheme iina

# Or open in Xcode
open iina.xcodeproj
```

### Regenerate mpv API Files (when updating mpv)
```bash
# Generates MPVOption.swift, MPVCommand.swift, MPVProperty.swift
other/parse_doc.rb

# Then copy from other/ to iina/ directory
```

## Code Style

- **Indentation**: 2 spaces (not tabs)
- **Line endings**: LF (Unix-style)
- **Encoding**: UTF-8
- **Trailing spaces**: Remove them
- **Final newline**: Required
- Use XIBs for UI elements when possible
- Follow macOS Human Interface Guidelines

## Critical Architecture Rules

### mpv API Access
**ONLY `VideoView` (iina/VideoView.swift) and `MPVController` (iina/MPVController.swift) may call mpv APIs directly.** All other code must go through the abstraction layers.

### PlayerCore Architecture
- `PlayerCore` (iina/PlayerCore.swift) encapsulates general playback functions
- **Do NOT** set options/properties directly through `MPVController` - use `PlayerCore` instead
- `PlayerCore` should only contain logic that controls playback
- Multiple `PlayerCore` instances can exist (one per window)

### Window Management
Window-related logic belongs in `MainWindowController` (iina/MainWindowController.swift):
- `windowDidLoad()`: One-time initialization
- `windowDidOpen()`: Called every time window is shown (for resetting UI components)
- `windowWillClose()`: Resource cleanup and deinitialization

### Generated Files - DO NOT EDIT
These files are auto-generated by `other/parse_doc.rb` and **must never be edited manually**:
- `iina/MPVCommand.swift`
- `iina/MPVOption.swift`
- `iina/MPVProperty.swift`

If you need to modify these, update `other/parse_doc.rb` instead.

## Project Structure

- `iina/` - Main Swift source code, XIBs, and localization files
- `iina-cli/` - Command line tool source
- `browser/` - Browser extensions (Chrome/Firefox)
- `OpenInIINA/` - macOS "Open in IINA" extension
- `iina-plugin/` - Plugin system
- `other/` - Build scripts and utility tools (Ruby)
- `deps/` - Pre-compiled dylibs and C header files
- `Configs/` - Xcode build configuration files (.xcconfig)

## Localization

- **Only edit** `Base.lproj` and `en.lproj` for UI strings
- **Never include** translations for other languages in pull requests
- Crowdin automatically syncs translations from `en.lproj`

## Pull Request Guidelines

- Target the `develop` branch (not master)
- Keep unrelated changes in separate PRs
- Watch for spurious changes:
  - `iina.xcodeproj/project.pbxproj` - Only include if you added/removed files
  - `.xib` files - Discard unintentional changes
- Rebase if develop has updated: `git rebase upstream/develop`

## Design Principles

- IINA is based on mpv - avoid features that mpv doesn't provide
- Consider Lua scripts for features mpv doesn't expose
- Provide users with choices when possible
- Use animations for UI transitions
- Maintain consistency with macOS built-in apps
- Proper margins and spacing everywhere

## Testing

There is **no automated test suite** - all testing is manual. When making changes:
1. Build and run the app
2. Test the specific functionality you changed
3. Verify no regressions in related features
4. Test on different macOS versions if UI/behavior changes

## Key Components to Understand

### PlayerCore Singleton Pattern
`PlayerCore` manages multiple player instances. Key static methods:
- `PlayerCore.first` - Get first player
- `PlayerCore.lastActive` - Get most recently active player
- `PlayerCore.active` - Get currently active player
- `PlayerCore.newPlayerCore` - Create new player instance
- `PlayerCore.activeOrNew` - Get active or create new

### Event System
`EventController` (iina/EventController.swift) and `JavascriptPlugin` handle the plugin event system.

### Preference Management
Preferences use `Preference` struct (iina/Preference.swift) with UserDefaults. Access via `Preference.enum` keys.

## Common File Operations

When working with player state or settings:
- Video filters: Use `PlayerCore.addVideoFilter()` / `removeVideoFilter()`, not direct mpv calls
- Audio filters: Use `PlayerCore.addAudioFilter()` / `removeAudioFilter()`
- Playback control: Always through `PlayerCore` methods (seek, pause, resume, etc.)
- Track selection: Use `PlayerCore.setTrack(_:forType:)`
