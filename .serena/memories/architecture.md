# IINA Architecture

## Core Components

### mpv Integration
- **Only** `VideoView` and `MPVController` may call mpv APIs directly
- Other components should go through the abstraction layers

### Player Core
- `PlayerCore` encapsulates general playback functions
- Setting options/properties directly through `MPVController` is discouraged
- `PlayerCore` should only contain logic that controls playback

### Window Management
- Window-related logic should be in `MainWindowController`
- `windowDidLoad()`: Initialization that should be done once
- `windowDidOpen()`: Resets/initialization for every time window is shown (window may not be loaded here)
- `windowWillClose()`: Resource cleanup and deinitialization

## Generated Files (DO NOT EDIT MANUALLY)
These files are generated by `other/parse_doc.rb` and must not be modified directly:
- `MPVCommand.swift`
- `MPVOption.swift`
- `MPVProperty.swift`

To regenerate these files when updating libmpv:
1. Run `other/parse_doc.rb` to fetch latest mpv documentation
2. Copy generated files from `other/` to `iina/`, replacing current files
3. If mpv API changes, player source code may also need updates

## Project Structure
- `iina/` - Main application source code (Swift, XIBs, localizations)
- `iina-cli/` - Command line tool
- `browser/` - Browser extensions (Chrome, Firefox) for "Open in IINA"
- `OpenInIINA/` - macOS extension for "Open in IINA"
- `iina-plugin/` - Plugin system
- `other/` - Build scripts and utility tools
- `deps/` - Dependencies (dylibs, header files)
- `Configs/` - Xcode configuration files (.xcconfig)
